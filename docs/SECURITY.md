# Security Policy

The security of Huddle and its users is important to us.

We appreciate the efforts of security researchers and community members who help identify and responsibly disclose vulnerabilities.

## Supported Versions

Security updates are provided for the latest stable release of Huddle.

| Version | Supported |
|---------|-----------|
| Latest stable release | Yes |
| Older releases | No |

## Reporting a Vulnerability

**Please do not disclose security vulnerabilities through public GitHub Issues, Discussions, or Pull Requests.**

If you discover a potential security vulnerability, please use GitHub's Private Vulnerability Reporting feature, if enabled for this repository.

Alternatively, contact the project maintainers through an officially documented private communication channel.

Do not share sensitive vulnerability details publicly before a fix is available.

## What to Include in a Report

Please provide as much information as possible:

- A clear description of the vulnerability.
- Steps to reproduce the issue.
- The affected Huddle version.
- The affected Linux distribution, if relevant.
- Potential security impact.
- Proof of concept or relevant logs, if available.

Please avoid including personal data, credentials, or other sensitive information.

## Security Considerations

The Huddle project pays particular attention to:

- Unsafe Rust code and memory safety.
- Dependency vulnerabilities.
- Improper handling of local files and user data.
- Unauthorized access to sensitive information.
- Unsafe command execution.
- Incorrect filesystem permissions.
- Security issues involving application configuration.
- Potential privilege escalation.
- Improper handling of external input.

## Response Process

When a vulnerability is reported, maintainers will:

1. Acknowledge receipt of the report.
2. Review and investigate the vulnerability.
3. Evaluate its severity and potential impact.
4. Develop and test an appropriate fix.
5. Release a security update when necessary.
6. Publish relevant security information when appropriate.

## Responsible Disclosure

We ask security researchers to give maintainers reasonable time to investigate and resolve reported vulnerabilities before making them public.

We appreciate responsible disclosure and collaboration.

## Scope

This policy applies to:

- The official Huddle source code.
- Officially maintained components.
- Dependencies and integrations maintained by the project.

Third-party software and Linux distributions may have their own security policies.

## Contact

For security-related matters, use GitHub Private Vulnerability Reporting when available.

Thank you for helping keep Huddle and its users safe.
